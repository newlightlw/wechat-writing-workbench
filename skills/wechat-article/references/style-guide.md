# 微信公众号文章写作风格指南

> 本指南基于参考文章 `knowledge-structuring-tutorial.md` 提炼，作为所有文章的统一写作规范。

## 基调与语言

### 对话感
- 使用第二人称"你"直接与读者对话
- 短段落，每段 2-4 句话
- 适当使用反问句制造节奏感
- 像在跟朋友聊天，不像在写教科书

### 节奏
- 先说"为什么"再说"怎么做"
- 每个大节开头用 1-2 句话解释这节的意义
- 从简单到复杂，逐步递进

## 标题设计

### 文章标题格式
```
用 [核心工具/方法] [动词] 你的 [成果]
```

**好标题示例**:
- `用 Obsidian + Claude 构建你的 AI 知识结构化系统`
- `用三步法搭建你的第一个 AI Agent`
- `用评测体系选对你的 AI 编程工具`

**标题钩子技巧**:
- 数字：`5 个步骤`、`3 种方案`
- 对比：`从 X 到 Y`
- 好奇：`你不知道的`、`被忽略的`
- 承诺：`一篇文章带你`

### 副标题格式
```
> 从 [起点] 到 [终点]，一篇文章带你 [承诺]
```

**示例**: `> 从信息碎片到结构化知识库，一篇文章带你从零搭建属于自己的"第二大脑"`

## 文章结构

### 章节编号
- 大节使用中文数字：`一、` `二、` `三、` ...
- 大节标题使用 `##` 级别
- 节内小节使用 `###` 级别
- 每节之间用 `---` 分隔

### 标准结构骨架
```markdown
# 标题

> 副标题

---

## 前言

[场景引入 + 问题定义 + 解决方案预告]

---

## 一、[第一节标题]

[先解释为什么，再展示怎么做]

### 1.1 [小节]

[内容]

📷 [截图位置：描述]

---

## 二、[第二节标题]
...

---

## 写在最后

[洞察 + 行动号召]

---

## 附录

### A. [参考资料/速查表]
### B. [工具链接]
```

## 排版规范

### 加粗
- 只标注**关键术语**和**重要概念**
- 不要整句加粗
- 不要滥用，每段最多 1-2 处

**正确**: 这套方案的核心工具组合是 **Obsidian** 和 **Claude Code**。

**错误**: **这套方案的核心工具组合是 Obsidian 和 Claude Code。**

### 表格
用于以下场景：
- 工具/方案对比
- 参数说明
- 功能列表
- 优劣对比

**格式**:
```markdown
| 工具 | 作用 |
|------|------|
| **Obsidian** | Markdown 笔记应用 |
```

### 代码块
- 命令行操作用 `bash` 语法高亮
- 配置文件用对应语言高亮
- 文件路径/URL 用普通代码块（无语法高亮）
- 代码块前说明用途，代码块后说明预期结果

### 引用块
- 提示：`> **提示**：内容...`
- 警告：`> **注意**：内容...`
- 费用说明：`> **费用说明**：内容...`

### ASCII 图表
用于：
- 目录结构
- 架构图
- 工作流程
- 概念关系

**目录结构示例**:
```
📂 你的知识库（Obsidian Vault）
├── 📁 raw/              ← 原始素材
├── 📁 wiki/             ← 结构化知识
└── 📄 CLAUDE.md         ← 规则文件
```

**工作流示例**:
```
┌─────────────────────────────────────┐
│            日常工作流                 │
│                                     │
│  1. 浏览网页 → 一键保存              │
│              ↓                      │
│  2. AI 阅读并结构化                  │
│              ↓                      │
│  3. 浏览知识网络                     │
└─────────────────────────────────────┘
```

## 截图标记规范

### 格式
```
📷 [截图位置：具体描述，突出关键元素]
```

### 标记位置
- 紧跟在相关文字或代码块之后
- 每个截图标记独立一行

### 描述要求
- 说明截什么界面/内容
- 用箭头/圆圈突出哪个元素
- 让人一看就知道要截什么

**示例**:
```
📷 [截图位置：Obsidian 官网下载页面，突出 macOS 下载按钮]
📷 [截图位置：终端中执行命令后的输出，以及 Obsidian 左侧文件列表显示 raw 和 wiki 文件夹]
📷 [截图位置：Obsidian 图谱视图，展示知识条目之间的链接网络]
```

### 截图密度建议

| 文章类型 | 建议截图数 | 分布 |
|----------|-----------|------|
| 工具教程 | 10-15 张 | 每个操作步骤 1-2 张 |
| 概念思考 | 3-5 张 | 关键架构图、对比图 |
| 实战经验 | 8-12 张 | 过程截图 + 结果展示 |
| 评测对比 | 5-8 张 | 评测环境 + 结果数据 |

## 开头写法

需要优化故事性开头时，按 [步骤 07 的可读性参考](../../wechat-07-humanize/references/readability.md) 选择有依据的事件或明确假设，组织动作、判断与读者问题。

### 前言（前言/引言）

**标准模式**:
1. 场景/痛点引入（你能共鸣的场景）
2. 问题定义（一句话说清楚核心问题）
3. 解决方案预告（告诉读者这篇文章会给出什么）

**示例**:
```
你是否经历过这样的场景：浏览网页时看到一篇好文章，随手收藏后就再也没打开过？

信息时代，我们缺的不是信息，而是把信息转化为知识的能力。

今天，我要介绍一套完整的知识管理方案，它能帮你：
- 快速采集
- 自动结构化
- 随时问答
```

## 结尾写法

金句应从作者已有判断提炼，原意、依据与取舍标准见 [可读性参考](../../wechat-07-humanize/references/readability.md)。正文关键位置也可少量使用，不固定每节一句。

### 写在最后

**标准模式**:
1. 提炼一个有洞察力的观点（不是简单总结）
2. 用类比或金句加深印象
3. 呼吁行动（鼓励读者动手）

**示例**:
```
这套系统的核心理念来自一个深刻洞察：**知识管理的本质不是存储，而是连接**。

开始动手吧。先用 Web Clipper 收集几篇你感兴趣的文章，然后让 AI 帮你把它们变成结构化的知识。
```

## 语言细节

### 用词偏好
- "你" 而非 "用户"
- "我们" 拉近距离（用于共同探索时）
- "建议" 而非 "必须"（除非真是必须）
- "看看效果" 而非 "验证输出"

### 避免的写法
- 避免大段理论堆砌，先给例子再总结
- 避免"众所周知"、"不言而喻"
- 避免过于口语化（如"超级好用"、"绝绝子"）
- 避免英文长句，中英混排时英文前后加空格

### 数字与单位
- 使用中文数字表达小数字（三步、五个）
- 大数字用阿拉伯数字（1000+、3.5B）
- 技术术语保留英文原文（Agent、RAG、Token）
