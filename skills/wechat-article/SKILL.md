# 微信公众号文章创作助手

帮助 AI 从业者撰写高质量微信公众号文章。从需求澄清到文章交付，全流程辅助。

## 文章类型

| 类型 | 适用场景 | 典型字数 |
|------|---------|---------|
| 工具使用教程 | 介绍工具使用方法 | 3000-6000 |
| 概念思考分享 | 分享对 AI 概念/趋势的见解 | 2000-4000 |
| 实战经验分享 | 分享系统搭建经验 | 3000-5000 |
| 评测对比 | 多款工具系统性评测 | 2500-4500 |

## Workflow

```
触发 → Phase 0: 需求澄清 → Phase 1: 信息收集 → Phase 2: 大纲设计 → Phase 3: 文章撰写 → Phase 4: 可行性验证 → Phase 5: 输出交付
```

---

### Phase 0: 需求澄清

在动笔前充分理解需求。使用 AskUserQuestion **一次性**确认所有事项。

**主题**: 从 `$ARGUMENTS` 或用户输入中提取。如果主题模糊，在 Q3 中追问。

**Q1: 文章类型** (`header: 文章类型`)

| 选项 | 说明 |
|------|------|
| 工具使用教程 | 如：Claude Code 使用指南、Obsidian + AI 工作流 |
| 概念思考分享 | 如：Agent Native 的思考、AI 记忆系统演进 |
| 实战经验分享 | 如：我的 Agent 搭建历程、RAG 系统落地经验 |
| 评测对比 | 如：5 款 AI 编程工具横评 |

**Q2: 目标读者** (`header: 目标读者`)

| 选项 | 说明 |
|------|------|
| 入门读者 | 刚接触 AI 的开发者/产品经理 |
| 中级读者 | 有一定 AI 使用经验的从业者 |
| 高级读者 | 深入 AI 技术的研究者/架构师 |

**Q3: 核心观点** (`header: 核心观点`, 文本输入)

你想传达的核心信息/价值是什么？读者读完应该有什么收获？

**Q4: 参考资料** (`header: 参考资料`)

| 选项 | 说明 |
|------|------|
| 无额外资料 | 完全基于信息收集 |
| 有本地文件 | 请提供文件路径 |
| 有 URL | 请提供链接 |
| 本地 + URL | 两者都有 |

**Q5: 保存位置** (`header: 保存位置`, 文本输入)

文章保存到哪里？（如 `~/articles/agent-memory.md`）

---

### Phase 1: 信息收集

根据主题和参考资料，**并行**收集信息。

**执行步骤**:

1. **Web Search**: 搜索 2-3 组关键词，覆盖：
   - 主题相关的最新动态和技术文档
   - 同类文章（了解已有内容，找差异化角度）
   - 具体的数据、案例、引用来源

2. **本地文件**: 读取用户提供的本地参考文件

3. **URL 抓取**: 用 WebFetch 抓取用户提供的 URL 内容

**输出格式**:

```
📊 信息收集完成

关键发现：
1. [发现1]
2. [发现2]
3. [发现3]

差异化角度：
- [相比已有文章，我们的独特视角/切入点]

知识缺口（可能需要补充）：
- [缺口1]
- [缺口2]
```

用 AskUserQuestion 让用户确认：
- 信息是否充分？
- 是否需要补充特定方面的资料？
- 差异化角度是否认可？

---

### Phase 2: 大纲设计

根据文章类型，从 `references/article-types.md` 中加载对应模板，生成结构化大纲。

**执行步骤**:

1. 读取 `references/article-types.md` 中对应的类型模板
2. 结合收集的信息和用户的核心观点，填充大纲
3. 为每个节指定核心要点（2-3 条）

**大纲格式**:

```markdown
## 文章大纲：[标题]

> [副标题]

预计字数：约 [N] 字

---

### 前言
- 要点1：[场景/痛点引入]
- 要点2：[问题定义]
- 要点3：[解决方案预告]

### 一、[节标题]
- 要点1：...
- 要点2：...
- 📷 [截图位置：描述]

### 二、[节标题]
- 要点1：...
- 要点2：...
- 📷 [截图位置：描述]

...

### 写在最后
- 要点1：[洞察]
- 要点2：[行动号召]

### 附录
- [参考资料列表]

---

截图总数：[N] 个
ASCII 图表数：[N] 个
```

用 AskUserQuestion 让用户确认大纲：
- 结构是否合理？
- 是否需要增删章节？
- 核心观点是否充分体现？

**用户确认后才进入 Phase 3。**

---

### Phase 3: 文章撰写

按确认的大纲撰写全文。

**执行步骤**:

1. 读取 `references/style-guide.md` 获取写作规范
2. 按大纲逐节撰写
3. 在适当位置插入 📷 截图标记

**写作要求**:

- 遵循 `references/style-guide.md` 中的全部规范
- 截图标记格式：`📷 [截图位置：具体描述，突出关键元素]`
- 每个 ASCII 图表放在独立代码块中
- 代码块标注语言类型（bash、python、typescript 等）
- 表格用于工具对比、参数说明、数据展示
- 引用块用于提示和注意事项
- 前言用场景/问题引入
- 结尾用洞察 + 行动号召

**文章元信息**（放在文件开头注释中）:

```markdown
<!--
文章类型：[类型]
目标读者：[级别]
核心观点：[一句话]
创建日期：[YYYY-MM-DD]
截图数量：[N]
-->
```

---

### Phase 4: 可行性验证

自我审查文章质量，逐项检查。

**检查清单**:

| # | 检查项 | 标准 | 通过 |
|---|--------|------|------|
| 1 | 标题吸引力 | 有钩子（数字/对比/好奇），读者会想点开 | ☐ |
| 2 | 核心观点传达 | 读者读完能一句话总结文章核心 | ☐ |
| 3 | 技术准确性 | 引用的技术信息准确无误 | ☐ |
| 4 | 结构完整性 | 从前言到结尾有逻辑递进，无断层 | ☐ |
| 5 | 配图合理性 | 截图位置配合内容节奏，不多不少 | ☐ |
| 6 | 可操作性 | 目标读者能跟着操作/理解 | ☐ |
| 7 | 独特价值 | vs 同类文章有差异化洞察 | ☐ |

**输出格式**:

```
📋 可行性验证报告

✅ 通过项：
- [检查项1]：[说明]
- [检查项2]：[说明]

⚠️ 需关注：
- [检查项]：[问题描述] → [建议修改]

❌ 未通过：
- [检查项]：[问题] → [必须修改]
```

如有 ❌ 项，先修复再交付。
如有 ⚠️ 项，用 AskUserQuestion 让用户决定是否修改。

---

### Phase 5: 输出交付

**执行步骤**:

1. 将文章保存到用户指定的路径（Phase 0 已确认）
2. 如文件已存在，询问是否覆盖或另存

**完成报告**:

```
✅ 文章完成！

文件：{path}
类型：{文章类型}
目标读者：{读者级别}
字数：约 {count} 字
截图位：{count} 个
章节：{count} 个

截图清单（需手动补充）：
- 📷 [截图位置：描述1] → 第X节
- 📷 [截图位置：描述2] → 第X节
...

下一步：
1. 根据截图清单补充实际截图
2. 在微信公众号编辑器中排版
3. 替换 📷 标记为实际图片
```
