# 思考天团

先识别用户给的是问题、大纲还是文章，以及需要解决的判断。默认在当前会话依次完成各视角分析；仅在用户明确要求或宿主任务已授权时使用多 Agent。

## 选择模式
- 通用分析：从 [顾问目录](references/advisors.md) 选择 2—3 个互补框架。用户指定顾问时尊重选择。
- 文章审稿：按 [审稿角色](references/editorial-board.md) 分别检查主线、读者理解、技术证据和传播承诺。
- 分歧辩论：先分别陈述主张与依据，再找出分歧来自事实、价值取舍还是适用条件。

领域聚焦时，只从该领域挑选框架；把 `--with` 理解为指定顾问、`--focus` 理解为领域聚焦、`--debate` 理解为分歧辩论，它们是自然语言调用约定，不是独立 CLI。

只读取本次选中的顾问 SKILL.md 或审稿参考，不一次加载全部顾问。
每个视角给出判断、依据、具体建议、不能确定的地方。模拟顾问的推演以“模拟视角”标注；引文须有原始来源，不把推演写成真人发言。

## 综合与交付
合并为共识、保留的分歧、必须修改、值得修改、保留不动以及下一步验证。多视角一致只表示模型内部意见趋同，不能证明事实或预测传播效果。

用户提供输出目录时保存综合稿与各视角文件；否则输出在当前对话，不写死个人目录。保存时使用：
- 0-综合汇总.md
- 1-顾问或角色视角.md（依次编号）

完成条件：每条修改意见指向具体段落或决策，行动能执行，证据缺口与分歧仍可见。示例见 [调用提示词](references/prompts.md)。
