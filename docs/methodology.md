# 实证写作方法

从真实问题中选题，用实践和研究形成判断，用多视角审稿改善表达，再用作者声音、图片、事实核对和排版完成交付。

## 写作原则

- 文章回答一个明确的读者问题，让读者带走一个判断或动作。
- 一手素材优先；结论可以是失败、无效或证据不足。
- 作者亲历、教学示例、他人结论、推测和规划分别表述。
- 数字有口径，技术能力有版本，效果有适用条件。
- 思考天团提供观察框架；多视角共识不替代证据。
- 可读性润色先从素材组织故事性开头，再提炼有依据的观点金句，最后校准作者声音。
- 去 AI 味保留判断、事实和个人声音，使用本人认可的样本校准。
- 正文讲清路线，详细命令和完整代码放配套资料。
- 截图展示真实状态，示意图解释概念；两者均有图注。
- 发布包完成、本地预览通过、真实平台验证分别记录。

## 操作流程

完整的 11 步、各步输入输出和提示词见 [首页](../README.md) 与 [提示词目录](../prompts/README.md)。
初次创作先做选题、brief、证据和大纲；已有初稿可以从审稿进入；事实纠错直接回到证据步骤。
标题在选题时可以试拟，正文完成后最终核对承诺。
重点长文增加人物框架或四角色审稿，普通短文不必叠加所有视角。

## 四种文章类型

1. 工具教程：准备条件、操作路线、预期结果、验收与排错。
2. 概念思考：问题、概念解释、论证、案例、局限与判断。
3. 实战经验：动机、选型、实现、失败、修复、结果与取舍。
4. 评测对比：任务、方法、环境与版本、数据、局限、按场景给建议。

模板见 [文章类型参考](../skills/wechat-article/references/article-types.md)，根据材料删减，不强求字数与章节整齐。

## 最小资料包

一份 brief、一张证据表、一份大纲、正文、必要图片及图注、发布检查说明。评审、提示词、历史稿与复盘按需保存。
新项目可从 [模板](../templates/README.md) 开始。

## 开源整理范围

这是个人写作实践的流程化整理，不是完整历史聊天导出。新整理的提示词与历史 skill 快照在来源说明中区分；私人文章、团队记录、聊天日志和凭证不进入发行包。

## 故事开头与金句怎样进入流程

原有文章模板已包含场景引入、洞察和结尾金句。v0.1.1 在步骤 07 补齐选材、改写与检查方法，步骤 08 再核对首屏承诺，规则集中在 [可读性参考](../skills/wechat-07-humanize/references/readability.md)。

故事来自有记录的经历、有来源案例或明确假设；金句提炼作者已经表达并能解释的判断。适用范围、证据和因果不因润色而扩大。短文或事实简报可以直接给问题与结论，不机械制造故事和名句。
